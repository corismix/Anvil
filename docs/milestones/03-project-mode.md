# Milestone 3 - Project mode + controlled dependencies

Status: complete. Verified green on main via CI run 33932563940 (https://github.com/corismix/Anvil/actions/runs/33932563940) at commit be01dc0.

## Goal

Raise the ceiling from one `ContentView.swift` to real multi-file apps,
without losing the no-Xcode build/run/export loop that makes Anvil not-a-
terminal.

## Current state (verified against code)

- Workspace agents (Codex, custom) run with the package root as their
  working directory, but `validateCodingAgentProtectedFiles` restores
  `Package.swift` and the app entry from baselines and DELETES any Swift
  file outside `Sources/<exec>/<exec>.swift` and `ContentView.swift`,
  failing the run with `CodingAgentError.protectedFileChanged`.
- `Package.swift` is regenerated by `ToolPackageMaterializer` from a
  fixed template (swift-tools 6.2, macOS 26, single executable target,
  no dependencies).
- Spark/Flame use the single-file generate/repair loop; workspace agents
  get the whole package root but the validation above keeps them
  single-file in practice.
- Git history (milestone 2) gives every accepted version a commit, so
  multi-file changes are diffable and restorable from day one.

## Design

### Generation mode

`ToolGenerationMode` gains `.project` alongside `.create`/`.edit` (those
two are lifecycle modes, not size modes - check actual enum before
naming; the user-facing choice is "Tiny App" vs "Project", stored as a
new preference on the Tool, defaulting to Tiny). Spark/Flame pipelines
reject Project mode in the UI (agent backends only).

### Project layout

```text
Sources/<Exec>/
  <Exec>.swift      # app entry - Anvil-owned, regenerated from settings
  ContentView.swift # root view - agent-owned
  **/*.swift        # anything else under Sources/ - agent-owned
```

### Protected-file rules in Project mode

- Anvil-owned (baseline-restored on tamper): `Package.swift` (see
  dependency flow below), the app entry file, `Legal/`, entitlements.
- Agent-owned: every other `*.swift` under `Sources/`. Create/edit/delete
  freely. `validateCodingAgentProtectedFiles` becomes mode-aware: in
  Project mode the disallowed-Swift-path check is dropped, and file
  deletions of agent-owned files stop being violations.
- Still forbidden outside `Sources/`: anything else (resources handled by
  the harness; milestone 4/5 may widen).

### Controlled Package.swift dependencies (allow/reject)

- Agents never edit `Package.swift` directly. They request changes via a
  structured channel: the agent writes `.anvil/package-request.json`
  (schema: `[{ "package": "<url>", "from": "<version>", "product":
  "<name>" }]`) and mentions it in its final message.
- After the agent run, the harness reads the request and presents an
  allow/reject sheet to the user: package URL, version, product, rendered
  as the exact manifest diff. Decision is remembered per app
  (`Tool.allowedPackageDependencies` - new persisted field, additive
  schema change ONLY if the current schema version is still unreleased;
  otherwise UserDefaults/keyed store per tool ID - decide at
  implementation, never mutate shipped schema versions).
- Allowed: materializer regenerates `Package.swift` with the dependency
  added, build proceeds. Rejected: the request is deleted and the agent's
  next repair turn is told the dependency was rejected (constraint
  feedback). No response to the request = treated as rejected.
- Free-form requests with human review (not a hardcoded allowlist).

### Repair loop in Project mode

Agent backends repair themselves (they see compiler output); the existing
post-run build verification stays. Spark/Flame single-file repair is
unchanged. Compiler errors map to files by the agent, not by Anvil's
single-file repair machinery.

### Mode migration

Tiny App -> Project: one-way, explicit user action in the app menu.
Content: existing `ContentView.swift` stays as root view; the mode flip
just relaxes validation and switches the prompt contract. Project -> Tiny
is not offered.

### Prompt contract

Workspace prompts (`CustomCodingAgentPrompt.compose`, Codex equivalent)
gain a Project-mode variant: multi-file layout description, protected
files list, dependency-request channel instructions.

## Resolved questions

- Allowlist vs free-form: free-form request + human allow/reject,
  remembered per app.
- Multi-file repair: agent backends self-repair; build verification stays
  with the harness.
- Mode migration: one-way Tiny -> Project, explicit.

## Testing

- Validation: Project mode allows extra Sources files, still restores
  Package.swift/entry on direct tamper; Tiny mode unchanged.
- Dependency request: parse/allow/reject flow, manifest regeneration with
  dependency, rejection feedback text, no-response = rejected.
- Mode migration: flip persists, validation switches.
- Full suite green via GitHub Actions before the milestone is marked done.
